# AFTERLIGHT — Development Constitution

**Authority:** Produced output of AF-096. Sits beneath `docs/CONSTITUTION.md` (AF-000, Master Constitution v1.0 — supreme) and `docs/MASTER_DESIGN_CONSTITUTION.md` (AF-014, highest creative authority beneath AF-000).

Uncertainty resolves *up* this chain. Nothing below may contradict anything above; this document never overrides AF-000 or AF-014, it operationalises them as a permanent, reusable review lens.
**Never replaced.** Extended only, exactly as every AF module is.

Where this document's vocabulary overlaps an existing authority (AF-014's Ten Commandments, Player Promise, or the Master Constitution's own Afterlight Test), the overlap is named explicitly below rather than restated as a second, competing rule.

## 1. Core Philosophy

Every decision must improve at least one of: **Gameplay · Player Experience · Scientific Plausibility · Replayability · Technical Quality · Accessibility · Artistic Identity · Long-Term Sustainability.** No feature exists purely because it is fashionable.

## 2. Design Pillars

Hope over despair · Discovery over repetition · Science over fantasy · Meaningful progression over grinding · Player freedom over restriction · Mastery over randomness · Horizontal expansion over power creep · Respect for player time · Technical excellence · Longevity.

*(Restates AF-014's Ten Commandments in "X over Y" form — same law, not a second one.)*

## 3. Non-Negotiable Rules

Never introduce: pay-to-win mechanics · artificial daily login pressure · mandatory FOMO · predatory monetisation · artificial grind · unreadable combat · unfair difficulty · contradictory lore · excessive UI clutter · needless complexity.

*(AF-014's Player Promise already forbids pay-to-win and artificial retention — this list is the fuller, checklist form of the same prohibition, extended with readability/clarity/lore/complexity failure modes AF-014 didn't enumerate individually.)*

Every new feature must justify its own existence against this list before it is built, not after.

## 4. Gameplay Governance

Every gameplay feature must improve at least one of: Combat · Exploration · Discovery · Build Diversity · Progression · Narrative · Replayability · Accessibility. **If it improves none of these, remove it.**

## 5. Content Governance

Every asset must possess: Purpose · Identity · Lore · Gameplay value · Technical efficiency · Expansion compatibility. Nothing exists as filler.

## 6. Quality Standard

Before becoming permanent, every new feature should achieve: High readability · Mechanical uniqueness · Technical stability · Strong visual identity · Excellent audio support · Accessibility compliance · Lore consistency · Performance compliance.

This is the same ≥9.5/10 bar every AF module has self-reviewed against since AF-079 (see `docs/modules/STATUS.md`'s Approved column) — this section names what that score is actually measuring.

## 7. World Consistency

All future content must remain consistent with: Scientific rules · Faction philosophy · Civilisation history · Technology progression · Timeline · **Art direction** · Audio identity · Narrative themes.

**Art direction, standing ruling (2026-07-09, Project Owner, amends `docs/TECHNOLOGY_DECISION.md`):** the primary art style is Nintendo-inspired stylized 3D mobile game art — chibi proportions, clean hand-painted textures, soft PBR lighting. This supersedes AF-002/092's prior 2D-flavoured art-style vocabulary wherever it conflicts. Any future content, module text, or design decision inconsistent with this style must be flagged to the Project Owner before proceeding, per the standing rule in `CLAUDE.md`. This is the permanent home for that ruling going forward.

## 8. Player Experience Priorities

Clear feedback · Rewarding discovery · Smooth progression · Meaningful decisions · Creative experimentation · Fair challenge · Player respect · Wonder. Every session should feel worthwhile.

## 9. Expansion Governance

Future expansions must: Extend, never replace · Support older systems · Respect previous content · Avoid invalidating builds · Avoid resetting progress · Preserve save compatibility · Expand the universe naturally.

*(This is the standing "modules are extended, never overwritten" rule from `CLAUDE.md`, restated at expansion scale — same law.)*

## 10. Technical Governance

Future code must remain: Modular · Documented · Maintainable · Scalable · Testable · Versioned · Optimised · Backward compatible. Technical debt should continually decrease. AF-094's Technical Architecture Framework and AF-095's Master QA Framework are this section's real, working enforcement layer, not aspirational duplicates of it.

## 11. Creative Governance

Maintain consistency across: Visual Direction (AF-092) · Music · Audio (AF-091) · Writing · UI (AF-093) · Gameplay · Animation · World Design · Marketing · Brand Identity. Afterlight should always feel unmistakably like Afterlight.

## 12. Permanent Review Questions

Before approving any feature, ask:

1. Does this improve gameplay?
2. Does it improve replayability?
3. Does it strengthen the universe?
4. Is it technically sustainable?
5. Does it respect player time?
6. Does it increase meaningful choice?
7. Is it accessible?
8. Can it scale for ten years?

**If any answer is "no", redesign it.**

*(Extends the Master Constitution's own "Afterlight Test" — same eight-question shape, with accessibility and ten-year scalability added as explicit, standing questions. Run this checklist, not a second one.)*

## 13. Success Metrics

The finished game should be recognised for: Exceptional replayability · Outstanding world building · Deep build diversity · Meaningful progression · Scientific imagination · Technical excellence · Accessibility · Player trust · Long-term support.
