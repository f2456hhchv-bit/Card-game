# The Civilisation Engine (AF-138)

Built entirely under `src/game/civilisationEngine/`, composing with — never redesigning — AF-090's real, locked `CivilisationFrameworkRuntime`. A dedicated research pass preceded design (the same research-first pattern used for AF-132/133/137) and confirmed the exact overlap before a single line of implementation was written.

## What's new

- **`civilisationEngineData.ts`** — `CIVILISATION_STAGES` (6: Survival → Beacon World) and `CIVILISATION_ENGINE_SPECIALISATIONS` (9) are new, separate classifications, deliberately never added to AF-090's own closed `SettlementDevelopmentStage` (7 values) or `CivilisationSpecialisation` (10 values) unions — different names, counts, and theming. `NEW_CIVILISATION_ATTRIBUTES` (10: Food/Water/Energy/Housing/Research/Culture/Ecology/Tourism/Innovation/Historical Preservation) are confirmed genuinely absent anywhere in the codebase. `CIVILISATION_ATTRIBUTE_TO_POPULATION_STAT` maps only the 5 `CivilisationAttribute`s that AF-090 actually live-mutates per settlement (Education/Health/Security/Public Happiness/Industry) — the research pass caught that `PopulationStat` also *declares* `population` and `employment`, but AF-090's `baselinePopulationStats()` never initialises either, so both are composed from other real sources instead (see below). `CIVILISATION_MEGAPROJECTS` (8) use distinct `megaproject-*` ids, never colliding with AF-090's real `MEGASTRUCTURES` ids despite two sharing generic display-name wording ("Orbital Ring," "Planetary Shield") with AF-090's `orbital-ring-frontier`/`planetary-shield-forge` — a documented, low-stakes vocabulary overlap, not an identity collision, so no Project Owner decision was needed (unlike AF-126's character rename). Also new: `CIVILISATION_LANDMARK_KINDS` (8), `IMMIGRATION_MOTIVATION_KINDS` (7), `SOCIAL_EVENT_KINDS` (8), `CAREER_PATH_KINDS` (7), `GENERATIONAL_CHANGE_KINDS` (4), `GALACTIC_IDENTITY_KINDS` (5), `PUBLIC_OPINION_REACTION_KINDS` (9), `GOVERNMENT_PRIORITIES` (6), and `civilisationStageFor` (a pure function over population + new-attribute average).
- **`CivilisationAttributeExtension`** — grow-only per-settlement tracking for the 10 genuinely new attributes.
- **`civilisationAttributeSummaryFor`** — the spec's own 18-attribute "Civilisation dashboard" (§Accessibility), composed live: 5 attributes from AF-090's real `SettlementState.populationStats`, Population from AF-086's real `CivilisationSimulationRuntime.stateFor(factionId)?.attributes.population` (per-faction, genuinely live — unlike AF-090's own unused `population` stat), Employment from a live-workforce-average proxy (`industrialWorkforce`/`scientificWorkforce`/`militaryPersonnel`, since Employment has no numeric home anywhere in the codebase), Infrastructure from a `builtUpgrades.size` proxy, and the remaining 10 from this module's own extension.
- **`MegaprojectTracker`** — mirrors AF-090's own `investInMegastructure` pattern over the new roster: real accumulating progress, capped at threshold, never double-completing.
- **`LandmarkRegistry`** — no new class; reuses AF-134's generic `MuseumCollectionRegistry<CivilisationLandmarkKind>` directly (its 6th distinct instantiation across AF-134/135/138).
- **`ImmigrationLedger`**, **`SocialEventCalendar`**, **`GovernmentPriorityTracker`** ("player influences direction, never absolute control" — influence only ever nudges a lean), **`PublicOpinionTracker`** (kept separate from AF-136's `StoryBranchTracker`, which is typed to a closed union), **`CareerPipeline`** (real per-citizen promotion counts).
- **Debug overlay** — `DebugSnapshot` gains a new `civilisationEngine` field, the same established per-module extension pattern used since AF-039.
