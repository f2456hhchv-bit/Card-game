# bossDirector — Boss Director (AF-057, game layer, inside `bosses/`)

**Purpose:** The orchestration layer OVER AF-035's locked `BossRuntime` — AF-056's conductor pattern applied to the climax. The runtime keeps owning phases, enrage, weak points, and its intro/death/ceremony state machine; the director owns everything BETWEEN those facts: between-phase breathing room during which the boss holds fire (recovery through repositioning, never artificial healing), a cadence-drained summon queue fed by a data-driven per-phase plan, arena escalation for the existing AF-035 hazard zone, cinematic one-shots (AF-053's consume-event shape, a third reuse), paced Reward Ceremony lines, and persistent Boss Memory through AF-026's stats.

**Responsibilities:** Beat/alteration/arena-feature/summon-kind/cinematic/legendary-moment/memory-key/multi-boss vocabulary, the pure `beatFor` derivation (live beat from the runtime's own state + the transition window), the sandbox summon plan, and director tuning (`bossDirectorData`); the transition/summon/ceremony clocks, the capped FIFO summon queue, cinematic one-shots, and the pure `fastestKillStatDelta` memory arithmetic (`BossDirector`).

**Dependencies:** none beyond its own data — the runtime is decorated purely through notifications (`notifyPhaseChanged`, `notifyDefeated`) driven by the composition root polling `BossRuntime.snapshot.phaseIndex`. `BossRuntime.ts`, `BossArena.ts`, and `bossData.ts` remain **byte-for-byte unmodified**. Summons materialise through the same shared `spawnEnemyInstance` path (elite guards via AF-034's unchanged elite flag); memory persists via `meta.recordStat` (attempts/victories/fastest-kill under `boss:{id}:*` keys).

**Data structures:** `BossDirectorRuntime`, `BossDirectorSnapshot`, `BossSummonSpec`, `SANDBOX_BOSS_SUMMON_PLAN`, `BOSS_DIRECTOR_TUNING`.

**Extension points:** new bosses bring their own summon plans (data, keyed by entered phase index — any enemy id, any faction); multi-boss kinds and legendary moments are registered vocabulary binding at future encounter modules; the four registered cinematic beats (camera events, lighting, music transition, dialogue) bind at the AF-002/006/045 asset and audio passes; loadout memory keys (commander/ship/weapon used) bind when the Hangar records per-run loadouts.

**Known limitations:** of the nine responsibilities, Introduction/Phase Transitions (AF-035), Music (AF-045's music state), and Narrative Events (lore notices) were already owned; the director adds Arena Control (hazard escalation), Summoned Enemies, Recovery Windows, and paced Reward Ceremony — Environmental Hazards beyond the existing zone are registered. Of the seven arena-control features, environmental hazards are live via the escalating AF-035 zone; the other six are registered. Live browser verification of the full decorated boss fight was NOT achieved in this module's session — the MiniBoss phase arrives ~98s into a run and the piloted player died at 14s/22s across two genuine attempts; the complete decorated encounter (phase change → held fire → in-order cadenced summons → victory cinematic) is instead verified against the REAL `BossRuntime` in `tests/bossDirector.test.ts`, and both live runs confirmed the wiring loads with zero page errors. The live-fight observation binds at the next session that naturally reaches the vault — the same documented-gap discipline AF-046 used for its mines.
